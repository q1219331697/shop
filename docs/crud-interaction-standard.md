# 后台 CRUD：弹窗改页面

## 1. 主旨 / 目标

将后台各管理模块中，以 **Dialog 弹窗**形式承载的表单类操作（新增、修改、详情、分配），重构为**独立页面（独立路由）**。

本文档**仅讨论"弹窗 → 页面"这一改造**，不涉及其他交互形态选择或组件内部实现方式的延伸。

---

## 2. 背景：当前现状

各模块普遍采用「列表页 + 弹窗」形态：

- **列表页**：`index.vue` 内嵌 `CrudTable`
- **新增 / 修改**：`CrudFormDialog`（`el-dialog`）
- **详情**：`CrudDetailDialog`（`el-dialog`）
- **分配角色 / 权限**：弹窗

以管理员管理为例，表单仅含 4 个字段（用户名 / 密码 / 姓名 / 状态），全部以弹窗承载。

---

## 3. 改造范围

以下操作由**弹窗改为页面**：

| 动作 | 原形态 | 目标形态 |
|---|---|---|
| 新增 | Dialog 弹窗 | 独立页面 |
| 修改 | Dialog 弹窗 | 独立页面 |
| 详情 | Dialog 弹窗 | 独立页面 |
| 分配（角色 / 权限等选择型） | Dialog 弹窗 | 独立页面 |

以下维持**弹窗（保持现状，不在本文档讨论范围内）**：

- 状态切换（启用 / 禁用 / 恢复）
- 删除、批量删除

---

## 4. 改造方式

对每个弹窗表单：

1. **新建页面组件**：如 `create.vue` / `edit.vue` / `detail.vue`，或用统一 `form.vue` + 路由参数区分新增与修改。
2. **新增路由**：在路由表中登记对应路径，例如：
   - `/system/admin/create`
   - `/system/admin/edit/:id`
   - `/system/admin/detail/:id`
3. **复用 schema**：页面内复用现有 `schema` 定义（`formFields` 等），保持字段、校验、校验规则与原弹窗一致。
4. **列表页跳转**：将原"新增 / 编辑 / 详情"按钮的"打开弹窗"逻辑改为 `router.push` 跳转；分配类按钮同理跳转至分配页面。
5. **返回逻辑**：保存 / 取消改为路由回退（`router.back()`）或跳回列表页。

---

## 5. 各模块映射（现状 → 目标）

| 模块 | 新增 | 修改 | 详情 | 分配 |
|---|---|---|---|---|
| 管理员 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 |
| 角色 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 |
| 权限 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 | 弹窗 → 页面 |

---

## 6. 实施注意

- **权限码不变**：`list / create / update / delete` 等后端权限码维持原值，本次仅改变前端承载形态，不改动接口或鉴权。
- **业务规则平移**：表单字段、校验、提交逻辑从原弹窗 schema 平移到页面，不应变更任何业务规则。
- **菜单与路由对应**：新增页面需与侧边栏菜单 / 路由保持对应，避免出现"有菜单无路由"或孤立页面。
